# 课堂随记：优化审计与优先 backlog

面向产品负责人的代码/安全/运维/体验审计。**本 PR 只提交审查结论，不实施大范围重构。**

审查基准：`main`（`118b91b`）。已假设 PR #1（`cursor/fix-orb-vertical-drag-417d`，悬浮球纵向拖动）会合并，下文不重复该项。桌面端当前仍存在该 bug，修完即可，不必另开任务。

## 执行摘要

- **可以开始信息房试运行，但不建议在「学生也能连上的校园网」上裸奔。** 设备侧接口按局域网便利设计：无绑定码也能列教室、拉座位、上传录音、写临时调课。学生手机连同一 Wi‑Fi 即可伪造课堂记录。
- **桌面悬浮球已锁死学校内网地址 `http://10.15.46.72:8020/`，** 设置页不再填写服务器/绑定码。这和 README、`快速开始.md`、`desktop/使用说明.md` 的操作说明不一致。换 IP、换端口或按文档本机 `localhost:3000` 启动，客户端会连错地方。
- **空数据/未排课的教室会展示错误名单：** 无座位时摊开全校学生；再不行就捏造「李明/王芳」等 demo 学生，录音还会写进真实数据库。试运行若导入不完整，教师会录到假人或别班学生。
- **网页采集端把设备绑定码放进 URL 查询参数**（`classroom.html?token=…`），并写入 `localStorage`。浏览器历史、投影截图、校园代理日志都会留下长期凭证。
- **ASR/LLM 会把未成年学生的姓名、班级、音频/转写和历史评价发到第三方。** 协议与重试在测试里是通的，但真实供应商质量、ffmpeg 依赖、单线程任务队列尚未按全校并发验证。
- **课表「教室课次总表」导入不检查与库中已有课表的冲突**（旧版「课程安排」导入会检查）。重复导入或补表容易造成「课表冲突，请联系管理员」，课堂端当场不能录音。
- **服务端查询几乎不做分页、索引很少：** 工作台每次把全表 `records`/`students`/`seats`/`schedule` 读出来再在 JS 里过滤。一学期后班主任打开页面会明显变慢。
- **文档承诺的能力有一部分还没落地：** 队列项删除、可配置服务器地址、`.env.example`、真实麦克风/PPT 置顶实测、Docker 在本环境未跑过。学校推广前应先做一个信息房闭环，而不是先拆 `server.js`。

## P0 · 试运行或联网前必须处理

### P0-1 局域网设备接口几乎无认证

- **问题：** `GET /api/device/rooms` 完全公开。`/api/device/state`、`/api/device/adjustments`、`POST /api/records` 在没有设备绑定码、没有登录 cookie 时，只要带 `X-Classroom-Room`（甚至 state 在缺省头时会落到第一间教室）即可读写。这是桌面端「选一次教室、日常免登录」的有意设计，不是疏忽，但默认监听 `0.0.0.0:3000`。
- **为何重要：** 校园网通常学生与教师同网。知道教室 ID（接口直接返回）就能：拉取学生姓名/学号座位、给任意学生写记录、把该教室本节课改成别的班。污染的是评价档案，不是演示数据。
- **建议方向：** 明确部署边界。最低限度：设备写接口必须持有绑定码或短期教室会话；`rooms` 列表不要对全网公开；防火墙只放行教师机网段；若必须保留 LAN 头，则仅允许来自教师机 IP 白名单。桌面端首次绑定仍可「选教室」，但应换成一次性配对码，而不是永久匿名头。
- **工作量：** M

### P0-2 未排课/未导座位时展示全校学生或虚构 demo 学生

- **问题：** `GET /api/device/state` 在匹配不到本节课名单时，依次回退：本教室全部座位 → **全库学生硬塞 6×6** → 六个写死的 demo（李明、王芳…）。`POST /api/records` 对 `demo-*` ID 会 `INSERT OR IGNORE` 成真学生。
- **为何重要：** 导课表不完整、课间、冲突节次，教师仍可能点到「假人」或别班学生并生成待审核记录。清理成本高，且会让试点老师失去信任。
- **建议方向：** 无当前课次时座位表应为空，并明确文案「当前无课 / 请调课」。Demo 学生仅允许在 `NODE_ENV` 开发开关下出现，生产禁止写入。
- **工作量：** S

### P0-3 桌面端写死学校 IP，与文档/默认服务端口冲突

- **问题：** `desktop/main.cjs` 中 `DEFAULT_SERVER='http://10.15.46.72:8020/'`。选教室、拉状态、保存配置都会强制写回该地址；UI 已去掉服务器和绑定码输入。后台默认却是 `localhost:3000`。README / 快速开始 / 桌面使用说明仍写「填写服务器地址和绑定码」。
- **为何重要：** 换机房、换端口、按官方文档本机演示、或把安装包发给另一所学校，客户端会静默打到错误主机。队列里的旧记录还会按保存过的 URL 继续上传（这点是对的），但新记录走错库。
- **建议方向：** 把服务器 origin 做成「打包时注入 / 首次配对 / 管理员下发」三选一，禁止把某校内网 IP 留在公开仓库默认值。同步改三份用户文档，避免两套操作手册。若当前只服务这一所学校，至少在使用说明首页用红字写死该 IP 和 8020 端口。
- **工作量：** S（先改文档+可配置项）/ M（正规配对流程）

### P0-4 网页采集端绑定码出现在 URL 里

- **问题：** 管理后台生成 ` /classroom.html?token=<一次性绑定码>`；`public/classroom.js` 读 query 后写入 `localStorage`，虽会 `replaceState` 去掉参数，但首次 URL 已进历史、代理、屏幕录制。
- **为何重要：** 绑定码等价于该教室的长期写权限（停用设备前一直有效）。投影、巡课拍照、把书签同步到个人账号都会泄漏。
- **建议方向：** 用一次性兑换码换本地保存的设备令牌（只在 POST 响应里出现一次）；书签只保存教室页，不含 secret。现有带 token 的链接做短 TTL。
- **工作量：** M

### P0-5 未成年学生音频与评价默认出域

- **问题：** 转写上传整段录音；分析请求带真实姓名、班级、课程时间和最多 12 条已确认历史评价。密钥可放 `.env` 或库内加密，但 README 声称的 `.env.example` **仓库中不存在**。DashScope 兼容路径还依赖本机 `ffmpeg`（Docker 镜像有，Windows 双击启动没有说明）。
- **为何重要：** 中小学场景涉及未成年人个人信息。供应商未签数据处理约定、未做本地/专有云、未告知家长时，试点有合规风险。ffmpeg 缺失时部分 ASR 会稳定失败，表现为「处理失败」，老师会以为是产品不好用。
- **建议方向：** 试点清单里写清：数据发给哪、能否用校园内网模型、音频保留多久。补 `.env.example`（无真实密钥）。安装说明写清：标准 multipart 转写不需要 ffmpeg；兼容模式/多模态路径需要。管理端对失败任务展示「缺 ffmpeg」而不只是泛化 HTTP 错误。
- **工作量：** S（文档与环境样例）/ L（本地模型或脱敏）

## P1 · 试点体验与数据正确性（建议 1–2 个迭代）

### P1-1 教室课次总表导入不检测与现有课表冲突

- **问题：** `kind=schedule` 的预览会用 `overlaps()` 拦截同教室时段冲突；推荐的 `kind=classroom` 只检查**本文件内**同一教室时段班级/教师/课程是否一致，提交时对旧课表是「按精确键删除再插入」，不同班级的旧行会留下。`resolveLesson` 遇到多条会进入冲突态，座位按钮全禁用。
- **为何重要：** 管理员按 README「推荐总表」操作，第二次补导或分年级导表后，课堂端最常见的现象就是「课表冲突，请联系管理员」。
- **建议方向：** preview/commit 复用 `overlaps()`（按教室 ID）；冲突行必须报行号。提供「覆盖本教室本学期」而不是静默叠加。
- **工作量：** M

### P1-2 网页采集端录音结束后麦克风不释放

- **问题：** `public/classroom.js` 的 `stopMediaTracks()` 在 `MediaRecorder` 仍为 `recording` 时只 `stop()` 录音器，**不** `stream.getTracks().forEach(t => t.stop())`。桌面 `panel.js` 和工作台内嵌采集页是停轨的。
- **为何重要：** 教师连续点多名学生时，浏览器标签会一直占着麦克风；部分一体机/平板第二次申请会失败，只能改用文字。
- **建议方向：** 与桌面端对齐：recorder stop 之后一定停轨。加一条回归测试或至少在采集页用可观察的指示灯。
- **工作量：** S

### P1-3 离线队列：死信、超时、不能删除

- **问题：** 桌面每 12s 全量重试；`flushPending` 对 4xx（学生不存在、教室不匹配）与网络错误一视同仁，没有退避。上传超时 15s，但音频以 JSON Base64 最大约 20MB，校园网很容易超时。设计文档写了「用户可删除队列项」，UI 只有重试。网页端 `flushQueue` 遇到第一条失败就 `break`，会堵住后面的成功项。
- **为何重要：** 一旦某条永久失败，磁盘上的 `pending.json`（含整段 Base64 音频）会一直胀；教师看到「N 条待上传」却不知道该丢哪条。
- **建议方向：** 区分可重试（网络/5xx）与死信（4xx）；指数退避；超时提到 60–120s 或改 multipart 直传；队列弹窗支持删除单条；网页端改为「失败跳过、继续下一条」。
- **工作量：** M

### P1-4 悬浮球在课件/PPT 全屏上的置顶与快捷键

- **问题：** `alwaysOnTop: true` 未指定 `screen-saver` 级别，也没有 `setVisibleOnAllWorkspaces({visibleOnFullScreen:true})`，未定时重新申明置顶。`Ctrl/Cmd+Shift+Space` 注册失败没有提示，与输入法/PPT 快捷键可能冲突，且不可配置。
- **为何重要：** 产品卖点就是「课件上方点名录音」。Windows 全屏幻灯片里球消失或快捷键无效，试点第一天就会被扔掉。README 已承认尚未做原生视觉实测。
- **建议方向：** 在教师机 Windows + WPS/PowerPoint 全屏、Mac 演示模式各测一遍；置顶用更高 level 并在显示变化时重申；快捷键可改、失败时在球上提示。不要在课间自动把面板弹到 PPT 前面（见 P1-5）。
- **工作量：** M（含真机）

### P1-5 课间自动弹出座位表

- **问题：** `selectPeriod` 在课间会指向**下一节**；`pollState` 每 15s 发现课次 key 变化且面板隐藏就 `toggle()` 打开。这是设计文档里的行为。
- **为何重要：** 下课铃后球会突然展开挡住课件收尾/下一班准备，教师会关掉常驻或卸载。
- **建议方向：** 仅在节次**开始后的短窗口**自动打开一次；课间保持收起，球上用小红点表示「下一节已匹配」。提供「不要自动弹出」开关（已有 keepOpen，语义不同）。
- **工作量：** S

### P1-6 工作台全表扫描，SQLite 几乎无索引

- **问题：** 唯一业务索引是 `records(class_id, created_at)`。`GET /api/records`、`/api/reports`、`allState` 都是 `SELECT *` 再在内存按权限过滤。`jobs` 每秒按 `status/next_at` 扫表。`sessions` 过期行从不清理。
- **为何重要：** 三机房试运行还能忍；一学期全校录音后，班主任每次打开「课堂记录」和「评价报表」会从数百毫秒变成数秒，SQLite 写锁也会更容易撞上 `busy_timeout=5000`。
- **建议方向：** SQL 侧按 `class_id`/`student_id`/`created_at` 过滤+分页；给 `jobs(status,next_at)`、`schedule(room_id,day,period)`、`sessions(expires)` 加索引；启动时删除过期 session。先不要上多进程写同一 sqlite。
- **工作量：** M

### P1-7 ASR/LLM 任务单线程、失败窗口偏短

- **问题：** `lib/ai.js` 全局 `running` 一次只跑一条 job，1s tick。失败 3 次即 `failed`，间隔 `attempts*15s`（约 15s+30s）。转写最长 120s，兼容 ASR 还要先 ffmpeg 30s。并发三间教室连续录音时，后面的记录会长时间停在「等待处理」。
- **为何重要：** 试点老师的心理预期是「下课后打开就能审核」。积压和三次网络抖动后变 failed，需要管理员点重试，现场会认为 AI「不稳定」。
- **建议方向：** 小并发（2–3）+ 按教室公平调度；对超时/429 用更长指数退避，不要把 401（密钥错误）和超时算进同一种 3 次；管理页突出 failed 原因。全校推广前用回放压一次队列。
- **工作量：** M

### P1-8 任课教师权限绑「姓名字符串」

- **问题：** `recordScope` / 录音前校验用 `lesson.teacher === u.name`。课表导入的「王老师」与账号姓名「王海涛」不一致则：看不见记录，或被拒绝录音。
- **为何重要：** 学校花名册、课表、系统账号三套名字几乎一定不一致。权限会表现为「偶发 403」，难以向老师解释。
- **建议方向：** 用户绑定教师标识（工号或课表教师名多别名），不要用显示名相等。短期可在创建账号时强制与课表教师列一致，并在 UI 提示。
- **工作量：** M

### P1-9 备份能做、恢复靠手、密钥不同步即废

- **问题：** `npm run backup` 会一致备份 sqlite + audio + `secret.key`（这点是对的），但会在备份进程里 `close()` 自己的连接；没有 restore 脚本、没有定时、Docker volume 未写备份策略。丢掉 `secret.key` 后库内 ASR/LLM 密钥无法解密。`启动管理后台.bat` 不加载 `.env`（`npm start` 会）。
- **为何重要：** 机房断电/误删 `data/` 是学校 IT 高频事故。只备份数据库不备份密钥，看起来「恢复成功」但分析服务全挂。
- **建议方向：** 提供 `npm run restore -- <dir>`（停服务、校验 key 与 db 成对、清 wal/shm）；Windows 任务计划示例；bat 与 `npm start` 对齐 `--env-file-if-exists`。
- **工作量：** S–M

### P1-10 三套采集前端逻辑分叉

- **问题：** 桌面 `panel.js`、网页 `classroom.js`、工作台内嵌 `classroomPage()` 各自实现座位、录音、队列、调课。网页端仍允许在设置里手填班级/教师并 POST 调课；桌面已改成「只选完整课次」。座位走道渲染也不一致。
- **为何重要：** 以后改匹配规则或录音协议要改三处，试点反馈会变成「网页可以网页不行」。
- **建议方向：** 先冻结「以桌面+device API 为准」，网页采集对齐桌面（无手选班级、无 demo、队列行为一致）。工作台内嵌采集可降级为入口链接，不必第三套座位实现。不要此时抽大框架。
- **工作量：** M

## 先不要做

这些要么与当前产品边界冲突，要么投入大、对一个信息房试点没有帮助：

## 一个信息房试点的最低闭环（建议顺序）

1. 确认网络隔离或完成 P0-1（否则学生可写记录）。
2. 按真实课表用总表导入，并补上 P1-1 的冲突检查；禁止 demo 回退（P0-2）。
3. 桌面安装包指向**实际**后台地址（P0-3），在教师机验证：拖动（PR #1）、PPT 全屏置顶、快捷键、断网录音再续传。
4. 配 ASR/LLM，用 3–5 段真实课堂录音走完「转写 → 待审核 → 班主任确认 → CSV」。确认 ffmpeg 需求与数据出域告知（P0-5）。
5. 班主任用自己的课表姓名/账号走一遍权限（P1-8）。
6. 做一次备份+恢复演练，包括 `secret.key`（P1-9）。
