# 课堂实例与节次驱动自动匹配设计

## 目标

教室设备无需教师登录或手动选择班级，在当前节次开始时自动识别教室、班级、教师和课程，并打开桌面悬浮窗口显示该班座位表。临时代课、调课或换教室通过客户端的“调换课”入口处理，不修改固定课表，课程结束后自动恢复固定安排。

## 核心关系

- 固定课表描述周期性安排：教室、班级、教师、课程、星期、节次、单双周。
- 节次时间由学校统一配置，教师和导入文件不填写开始/结束时间。
- 课堂实例是某个日期内的具体上课单元，记录实际采用的课表来源（固定或临时）。
- 学生课堂记录必须绑定课堂实例，并保存教师、班级、教室、课程等快照。
- 座位表按“教室 + 班级”生效，同一班级在不同教室可以拥有不同座位。

## 自动匹配

服务端根据设备绑定的教室、北京时间、日期和节次查询当前课次。临时调整优先于固定课表；无临时调整时使用固定课表。匹配到零条时显示无课，匹配到多条时显示冲突并拒绝猜测，不取第一条。

桌面端轮询状态，在课次发生变化时刷新并自动打开悬浮窗口。窗口展示当前课堂实例和班级座位，记录提交时携带课堂实例标识。

## 临时调课

客户端点击“调换课”后，教室自动带出，用户只选择日期和第几节课；系统列出该时间段可用的完整课次（班级、教师、课程），用户选择后生成临时调整。临时调整包含原课次、实际课次、调整原因、操作设备和创建时间，作用范围仅限指定教室、日期和节次。固定课表保持不变，节次结束后临时调整自动失效。

## 资料职责

- 管理员维护教师、班级、学生、教室、设备、节次时间、固定课表、座位和临时调整。
- 教师日常不填资料；可使用悬浮窗口记录学生表现，必要时发起临时调课。
- 班主任查看授权班级记录并完成转写修正、评价审核和导出。
- 学生不登录，仅通过名单和座位资料被系统识别。

## 兼容策略

现有开始/结束时间字段保留用于历史数据兼容和系统计算，但新导入模板以“节次”为主。旧数据启动时按已有时间匹配；新数据优先使用节次。记录中继续保留教师和课程快照，确保历史数据不受后续课表调整影响。

## 验证重点

- 节次边界、单双周、具体日期覆盖和跨天重启。
- 同一教室同一节次冲突时不自动选择。
- 临时调课优先级、结束后恢复固定课表。
- 设备状态返回课堂实例及座位，记录绑定实例且重复提交幂等。
- 旧版时间课表和新版节次课表可同时工作。
